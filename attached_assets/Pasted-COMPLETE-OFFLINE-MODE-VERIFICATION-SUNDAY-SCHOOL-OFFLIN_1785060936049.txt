PART B — ADD SUNDAY SCHOOL OFFLINE ARCHIVE SUPPORT
==================================================

Extend the existing Offline Mode so that previous Sunday School lessons and the complete previous Sunday School archive can be downloaded and read offline.

1. PREVIOUS SUNDAY SCHOOL LESSONS

- Every past Sunday School lesson must have a clear “Download for Offline Use” button.
- Once downloaded, the lesson must open without internet.
- Store the downloaded content in the user’s device/app local storage through the existing IndexedDB and Cache Storage system.
- Do not create duplicate copies on our server.

Store, where available:
- lesson title
- lesson date
- scripture reference and scripture text
- lesson body
- memory verse
- lesson objectives
- questions
- teacher notes
- permitted attached PDF
- permitted attached image
- language
- Bible translation
- content version or last-updated value

Do not automatically download:
- videos
- audio
- unusually large files
- external resources that cannot safely be cached

2. COMPLETE PREVIOUS ARCHIVE DOWNLOAD

Add a Sunday School offline archive section with:

- Download All Previous Lessons
- Download by Year
- Download Individual Lesson
- Update Downloaded Lesson
- Remove Individual Download
- Remove Year
- Clear Entire Sunday School Offline Archive

Before a bulk download:
- show the estimated storage size when technically possible;
- clearly explain that the lessons will use storage on the user’s phone or device;
- ask the user to confirm;
- allow the user to cancel before the download starts;
- show progress during the download;
- handle partial failure without corrupting completed downloads.

“Download All Previous Lessons” must include only lessons already published before the current lesson date. Do not silently include future lessons.

3. STORAGE MANAGEMENT

Inside My Library or Offline Content, add a section named:

Sunday School Offline Archive

Show:
- number of downloaded lessons
- years downloaded
- storage used
- last updated date
- available device storage when supported by the browser
- download progress where applicable
- delete controls
- a warning before clearing all downloaded Sunday School content

Do not silently consume excessive storage.

4. OFFLINE ACCESS

When the user has no internet:

- Downloaded Sunday School lessons must open normally.
- A non-downloaded lesson must show:

“This Sunday School lesson is not available offline. Connect to the internet and download it first.”

- Show an Offline or Available Offline badge on locally stored lessons.
- The archive list must clearly show which lessons are downloaded.
- Do not show an endless loading state when the network is unavailable.
- If an attached PDF or image was not cached, explain that the attachment is unavailable offline while still displaying the lesson text.

5. CURRENT AND FUTURE LESSONS

- Current and future Sunday School lessons remain online by default.
- A user may manually download a current lesson once it is published and available.
- Do not automatically download current or future lessons without the user’s permission.
- Do not prefetch unpublished lessons.

6. UPDATES AND SYNC

When the device reconnects:

- Check whether a downloaded lesson has a newer version.
- Do not automatically delete or overwrite the local copy.
- Show “Update Available.”
- Allow the user to refresh the downloaded lesson.
- Preserve any locally saved personal notes.
- If the update fails, retain the previous working offline copy.

Online-only activities such as:
- attendance
- comments
- assignments
- quiz submissions
- teacher updates
- grading
- member-specific records

must remain unavailable offline unless the app already has a safe and tested offline queue.

Do not invent a new syncing system for sensitive or account-specific data.

7. PHONE AND DEVICE STORAGE

Use the existing browser/app local storage system, including IndexedDB and Cache Storage where appropriate.

- Do not rely only on React state or memory.
- Do not claim content is saved in the public Files folder unless that is genuinely supported.
- Downloaded lessons must remain available after closing and reopening the installed app or browser, subject to platform storage rules.
- Handle Safari and Android Chrome storage limitations gracefully.
- If storage is full, unavailable, evicted, or permission is restricted, show a clear human-readable message.
- Request persistent storage through the browser Storage API when supported, but do not block the feature if the request is denied.
- Do not store sensitive user, authentication, payment, counseling, or private church data.

8. ARCHIVE ORGANIZATION

Organize downloaded Sunday School content by:

- year
- month
- lesson date
- lesson title

Add search and filtering for downloaded Sunday School content only if the existing archive or Offline Content page already has reusable search/filter support. Do not build an unrelated search system from scratch.

9. LANGUAGES

Add every new Sunday School offline label and message to:

- English
- Spanish
- French

Keep all three locale files in full key parity.

Downloaded lessons must preserve the exact language version selected by the user at download time.

Do not falsely claim that the lesson content itself has been translated when only the interface labels are translated.
