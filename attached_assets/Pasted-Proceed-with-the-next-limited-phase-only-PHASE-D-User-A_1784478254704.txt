BUILD NOW — PHASE D ONLY
==================================================

1. REUSE THE EXISTING AUTHENTICATION SYSTEM

Inspect the current authentication system and reuse it.

Do not create a second or competing login system.

Support the safest existing account flow already available in this project, including:

- Email sign-up
- Email sign-in
- Sign-out
- Password recovery or approved passwordless recovery

Rules:

- Do not store plain-text passwords.
- Do not expose authentication secrets.
- Do not break existing admin login.
- Do not force users to sign in just to read devotionals, browse songs, listen, view lyrics, share, or submit testimonies.

==================================================
2. ADD “SAVE TO MY LIBRARY”
==================================================

On each SpiritTone Music song-detail page, add a clear button:

“Save to My Library”

When a signed-out user taps it, show:

“Create or sign in to your free 365 Daily Devotional account to keep your saved songs and favorites available across your devices.”

After successful sign-in:

- Return the user to the same song.
- Complete the save action automatically.
- Show a confirmation message.
- Do not make the user search for the song again.

For signed-in users:

- Save the selected song to that user’s personal library.
- Prevent duplicate saved-song records.
- Allow the user to remove the song later.
- Removing from My Library must never delete the ministry’s master song record.

==================================================
3. CREATE “MY LIBRARY”
==================================================

Add a user-facing “My Library” section inside the existing account/profile area.

For this phase, My Library should include only:

- Saved Songs
- Favorite Songs
- Downloaded Songs or Download History, only if Phase C already stores this safely

Each saved-song card should display:

- Cover thumbnail
- Song title
- Artist or vocalist
- Scripture reference
- Play
- Open Song
- Remove from My Library

Do not build books, devotionals, prayer history, counseling history, playlists, or subscriptions in this phase.

Prepare the layout so those categories can be added later without redesigning My Library.

==================================================
4. CROSS-DEVICE SYNCHRONIZATION
==================================================

Saved songs and favorite songs must be linked to the authenticated user account, not only to local browser storage.

Required behavior:

- A user saves a song on one device.
- The same song appears after the user signs in on another device or browser.
- Removing a saved song updates the user’s account everywhere after normal refresh.
- One user must never see another user’s saved songs.
- Preserve any existing local favorites safely.

If local song favorites already exist:

- Do not delete them.
- After a user signs in, offer or safely perform a one-time migration of local song favorites into that user’s account.
- Prevent duplicates.
- Do not migrate unrelated local-storage data.

==================================================
5. FAVORITE SONGS
==================================================

Update the existing song Favorite action so:

- Signed-in users have favorites stored in the database and synchronized across devices.
- Signed-out users may continue using device-local favorites temporarily.
- When they later sign in, safely merge those local favorites into their account.
- Do not break devotional favorites.
- Do not use the same storage key or table in a way that mixes devotional and song favorites.

==================================================
6. DOWNLOAD HISTORY
==================================================

Only if Phase C already supports safe free promotional downloads:

- Record a lightweight download-history entry for signed-in users.
- Store song ID, user ID, and download date.
- Do not store downloaded audio inside the database.
- Do not count an attempted or failed download as successful.
- Do not create analytics dashboards in this phase.

For signed-out users:

- Free promotional download may still work if already allowed.
- Do not force sign-in merely to download unless the existing design specifically requires account tracking.
- Invite them to sign in to preserve the download in My Library, but do not misrepresent the file as cloud-stored when it is only on their device.

==================================================

When an unsigned user clicks:

- Save to My Library
- Cloud Favorite
- View My Library

open the sign-in flow and return them to the intended action afterward.

==================================================
8. DATABASE AND SECURITY
==================================================

Use the smallest safe additive data structure needed for:

- User saved songs
- User favorite songs
- Optional download history

Reuse existing user IDs and authentication relationships.

Security rules:

- Only the authenticated user may read or modify their own saved-song records.
- Admin may manage master songs but should not browse private user libraries unless explicitly required for support and already permitted.
- Regular users must not edit or delete master song records.
- Add or preserve row-level security where applicable.
- Do not expose private emails publicly.
- Do not log passwords, tokens, or private account data.
- Do not weaken existing authentication.
- Do not create public write access.

- Do not clear devotional, prayer, counseling, or admin caches.
