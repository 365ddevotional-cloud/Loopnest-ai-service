PHASE 1 — MUSIC PLAYBACK MODES
==================================================

Add these playback modes to the existing shared music player.

1. NORMAL PLAYBACK

- Play the selected song normally.
- Stop when it finishes unless the existing queue already specifies a next song.
- Clearly show that no repeat mode is active.

2. REPEAT ONE

- Continuously repeat the currently playing song.
- Use the existing audio element’s loop behavior where appropriate.
- Show a clearly highlighted Repeat One state.

3. PLAY ALL

- Starting with the selected song, automatically continue through every song in the CURRENT ACTIVE LIST.
- The active list means the songs currently visible through the selected:
  - language
  - collection
  - search result
  - genre
  - song type
  - active filter
  - full music library
- Stop after the final song.

Examples:

- If Spanish is selected, play all currently visible Spanish songs.
- If a collection is open, play all songs in that collection.
- If search results are displayed, play only those results.
- If no filter is active, use the complete active music library.

4. REPEAT ALL

- Play every song in the current active list.
- After the final song finishes, return to the first song and continue.

5. SHUFFLE

- Randomize playback within the current active list.
- Avoid immediately replaying the same song when more than one song exists.
- Shuffle may work together with Play All or Repeat All only if that is safe within the current player architecture.
- Do not create contradictory or confusing mode states.

PLAYBACK-MODE USER INTERFACE

Add a compact playback-mode control to:

- the full song player;
- the persistent or mini-player where space permits;
- the main Music Library page.

Include accessible labels or tooltips:

- Normal Playback
- Play All
- Repeat One
- Repeat All
- Shuffle

Use familiar playback icons where appropriate.

Show the active mode clearly with the existing orange SpiritTone accent.

Add a prominent “Play All” button near the top of the Music Library.

Persist the chosen playback mode in localStorage so it remains selected after refresh. An account must not be required.

Playback-mode changes must not:

- restart the song unnecessarily;
- increase the play count;
- open another audio stream;
- lose the current playback position;
- break the existing queue or recently played behavior.

   - touch
   - pointer
   - mouse
   - keyboard
3. Use `onInput` for immediate updates while dragging.
4. Retain `onChange` as a compatibility fallback where useful.

7. Listen for `volumechange`.

14. Save the preferred volume in localStorage where permitted.
15. Restore the saved volume after refresh and when a new song begins.
16. Do not restart playback when volume changes.
17. Do not increase the play count when volume changes.

Do not assume every mobile browser permits programmatic media-volume control.

- attempt to set the volume;
- read back the actual value;
- observe whether a volumechange event occurred;
- do not rely only on browser-name detection.

If the mobile browser does not permit webpage-controlled volume:

- do not leave a slider that falsely appears to work;
- show a short message:
  “Use your phone’s volume buttons to adjust sound.”
- keep mute/unmute where supported;
- do not repeatedly show alerts;
- do not describe this as an app failure.

Do not allow:

- horizontal page scrolling;
