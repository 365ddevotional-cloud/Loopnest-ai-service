PART 1 — SECURE THE YOUTUBE OAUTH FLOW

The current YouTube OAuth implementation is missing proper OAuth state/CSRF protection.

Fix this without changing the existing YouTube architecture.

Requirements:

1. Generate a cryptographically secure random OAuth state value on the server before redirecting the administrator to Google.
2. Store the state temporarily on the server using the project’s existing secure session, database, or server-side storage pattern.
3. Include the generated state in the Google OAuth authorization URL.
4. When Google redirects to the OAuth callback, compare the returned state with the stored state.
5. Reject the callback if:
   - state is missing;
   - state does not match;
   - state has expired;
   - state has already been used.
6. Make each state single-use.
7. Apply a short expiration period, such as 10 minutes.
8. Do not place secrets, access tokens, refresh tokens, or sensitive session information in URLs, browser storage, logs, or API responses.
9. Preserve the existing YouTube callback route and connected-channel behavior where possible.
10. When Google credentials are absent, keep the integration safely disabled and show the existing clear configuration message.
11. Do not attempt a real OAuth connection during this task because GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET have not yet been configured.

PART 2 — NEXT AND PREVIOUS TRACK CONTROLS

Add compact Previous Track and Next Track buttons to the existing music player.

Place them where appropriate in:

- the full song player;
- the persistent or mini-player;
- any existing playback control area that already supports queues.

Behavior:

Previous Track:
1. If the current song has played for more than approximately 3 seconds, restart the current song from the beginning.
2. If it has played for less than approximately 3 seconds, move to the previous song in the active queue.
3. If the current song is the first song:
   - Repeat All may wrap to the final song;
   - otherwise remain at the first song.
4. In Shuffle mode, return to the previously played song using playback history when available.

Next Track:
1. Move immediately to the next song in the active queue.
2. Respect the current playback mode:
   - Normal;
   - Play All;
   - Repeat One;
   - Repeat All;
   - Shuffle.
3. When Repeat One is active, manually pressing Next should still move to the next available song rather than replaying the current one.
4. At the final song:
   - Repeat All should return to the first song;
   - Play All and Normal should stop or remain at the final song according to the existing player behavior.
5. Do not allow two audio elements to play simultaneously.

Use accessible labels and tooltips:

- Previous Track
- Next Track

Show the controls clearly on desktop and mobile without causing horizontal overflow.
