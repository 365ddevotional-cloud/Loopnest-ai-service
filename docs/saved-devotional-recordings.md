# Saved devotional narration

Owner requested dependable Yoruba audio after the device reported no yo-NG voice. This adds a provider-independent saved-recording path. It does not add or call a speech provider, activate paid generation, create a subscription or create another hosting service.

Admin → Content translations now shows a saved-recording studio for each published translation. It gives the exact recording script, accepts an MP3 up to 20 MB, saves it privately, and offers an audition. Publication requires a separate full-recording review and confirmation of publication rights. An uploaded file is not automatically published. The script preserves the existing original English Scripture quotation; Bible translation is outside this change. Human recordings and legitimately licensed synthesized recordings can use the same path.

The SHA-256 version covers the exact script, devotional ID, date and language. A changed script cannot use the old recording. Every delivery rechecks current saved text and publication status; deleted, future, unavailable-language and mismatched versions fail closed. Existing approved translations already fail back to English if their original source changes. Uploads and publication require the existing admin session and same-origin writes. Publication is bound to the reviewed file's SHA-256, and conditional ETag writes prevent concurrent changes from replacing another review.

Recordings and small manifests use a dedicated devotional-recordings prefix in the existing private shop R2 bucket. The public music bucket is never used. No database table or infrastructure change is needed. Public readers receive a same-origin delivery path; the server signs a private object for 120 seconds. Already issued links can remain usable for that interval after unpublication. MP3 delivery goes directly from R2 with native range support. Storage and delivery remain subject to the existing hosting/storage plan; replaying does not generate speech or incur another provider synthesis charge.

Published recordings use native HTML media controls and start directly inside the Listen tap, without device Yoruba speech support. Native controls provide pause, seek and platform playback options. The existing device reader remains available when no published recording exists. Recording loading errors are visible. The app cannot certify physical iPhone sound remotely.

No recording was generated, uploaded or published as part of implementation. No provider credential or generation spending allowance is present. The owner must supply an authorized recording or approve access and a spending limit for a Yoruba-capable provider. Voice output must be auditioned before publication. Do not claim the saved recording is live until one is actually uploaded and released.

Provider research on 2026-11-19: ElevenLabs lists Yoruba and Hausa in Eleven v3 and newer voice models. Its API pricing lists v3/v4 at $0.08 per 1,000 characters and v4 Turbo at $0.04 per 1,000; these are indicative generation costs, not an account quote or authorization. Commercial publication rights and any required plan/prepayment must be verified on the actual account before generation. The pricing page lists Starter at $6 monthly with commercial licensing; promotions and plan allowances vary. The current pilot Yoruba script is approximately 3,247 characters before removal of display-only Scripture markers; use the studio's actual count for a quote. No inference of reliable native Pidgin support is made.
